# 多语言与多币种兼容审计

审计基线：v2.4.2（`496dd2e`）

## 结论

- 多语言应继续使用同一份 userscript，在设置内选择“跟随 Steam / 简体中文 / English”。不建议复制成另一份插件：两份脚本会重复全部业务逻辑，并让修复、配置迁移和发布长期分叉。
- 翻译层应只替换用户可见文字，市场和徽章解析继续固定请求英文页面。这样界面语言不会改变解析结构，也不会要求为每种 Steam 语言维护一套解析器。
- 当前 userscript 为 334,050 B。源码中约有 746 条不同的中文字符串，UTF-8 文本约 43 KB；完整加入一套英文翻译预计使生产脚本增加约 25–45 KB。对 Tampermonkey 仍可接受，但应在实现后以实际构建结果复核。
- 当前不能宣称完整多币种支持。CNY、USD、HKD 已有明确的格式和手续费定义；其他 Steam 币种只能得到通用显示上下文，零小数位、三小数位、符号位置和最低价格均可能不正确。

## 当前多语言兼容情况

- UI、日志、确认窗口和空状态文字直接写在各功能模块中，尚无统一翻译入口。
- 多处排序固定使用 `zh-CN`，日期和数字也有中文区域格式。
- 徽章页、挂牌页和买单页有一部分请求固定使用英文，这是有意的解析稳定策略，应保留。
- 库存请求跟随 Steam 当前语言；物品名称可以保持 Steam 返回的本地化名称，不需要再由脚本翻译。

建议新增一个轻量 `i18n` 服务：

1. 使用稳定 key 保存简体中文和英文词典，并支持参数插值。
2. 配置保存 `auto`、`zh-CN` 或 `en-US`；`auto` 优先读取 Steam 页面语言。
3. UI、日志和确认信息统一调用翻译函数；排序和日期使用当前 UI locale。
4. 网络请求的解析语言与 UI 语言分离，继续固定使用英文结构。
5. 首次实现只包含简体中文和英文；以后增加第三种语言时再评估按需语言包，当前无需引入远程资源。

## 当前多币种兼容情况

已经具备：

- 从钱包、页面或设置识别 currency ID。
- 市场缓存、订购缓存和价格历史按币种隔离。
- CNY、USD、HKD 的金额解析、显示和市场请求已有测试。

仍需补齐：

- 价格上限、买价调整和自动策略偏移仍有多处按 `×100` / `÷100` 计算，并固定使用 `0.01` 输入步长，只适合两位小数币种。
- 回退币种设置目前只允许 CNY、USD、HKD。
- 未知币种使用通用两位小数格式，但没有经过真实最低价和手续费验证，不应允许写入订单或市场操作。
- 代码中仍保留旧 CNY 字段的只读迁移兼容；它不影响当前三种币种，但不应继续扩散到新功能。

扩展新币种时，应先取得该币种的钱包信息、`priceoverview`、挂牌订单簿和最小价格样本，再增加币种定义与测试。所有用户输入金额应通过当前币种的 `minorUnitFactor` 转换，确认格式和手续费后才开放下单、出售或撤单金额计算。

## 推荐实施顺序

1. 先建立翻译服务并迁移主弹窗、设置和确认窗口，再迁移日志与少见错误提示。
2. 消除业务代码中的固定 `100` 和 `0.01`，使金额输入按币种精度工作。
3. 为零小数位、三小数位及符号后置币种补真实夹具。
4. 只有验证完成的币种才出现在设置列表中；无法确认币种时继续禁止下单和出售。
